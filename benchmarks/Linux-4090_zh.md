# Linux · NVIDIA RTX 4090 性能

[English](Linux-4090.md) · [性能索引](../BENCHMARK_zh.md) · [模型与精度](../MODEL_ZOO_zh.md)

以下为 SAM 3 在注明硬件与负载下的既有测量；权重名称表示存储格式，
计算和状态格式遵循模型与后端的精度策略。

权重均为官方 SAM 3 `sam3.pt` checkpoint 的 GGUF 导出。

## Linux CUDA 测量

测量日期：2026-10-07，Asia/Shanghai。Intel Core i7-12700KF，20 个逻辑 CPU，
操作系统可见内存 32.606 GB；NVIDIA RTX 4090，24,564 MiB 显存，功率上限 500 W；
Linux x86_64，内核 7.0.0-31，GCC 15.2、NVCC 13.3.73、驱动 610.57.04。
Release 构建使用带项目补丁的 GGML 0.25.3。CPU/BLAS 使用 OpenBLAS 0.3.32
（pthread）并请求四线程；CUDA 使用 cuBLAS，关闭 CPU BLAS 后端及 CUDA graph capture。各配置在桌面
运行期间串行测量，与 [macOS M4 Pro 测量](MacOS-m4pro_zh.md)分别记录。

## 文本提示图像分割

采用相同的 1800 × 1200 RGB PPM、`truck` 提示词及 1008 × 1008 模型输入，
执行一次冷调用、五次非缓存完整图像调用和五次独立缓存重放。表中给出五次完整
调用的中位数与 P95，不含模型加载、外部解码、文件输出及缓存重放。列出的每项
配置均在计时前通过全部七个原始参考图像用例。CPU/BLAS 单元格为秒 / 峰值 RSS GB；
破折号表示该项未计时。

CUDA 进程 RSS 与 GPU 内存分别统计。RSS 来自计时进程。图像显存使用相同负载与
构建的独立进程，由 `nvidia-smi` 约每 50 ms 采样，包含 context 和 pools；
视频显存在计时期间约每秒采样。采样可能遗漏瞬态峰值，数值是真实进程峰值的下界。GB 为十进制；
P95 按 `(n-1)*0.95` 位置线性插值。

量化 CUDA 使用原生压缩权重 kernel、RHS Q8_1 staging 及独立算术 profile。
验收检查最终输出质量，不代表逐张量等价于 F32。详见[量化使用指南](../docs/quantization_zh.md)。

下面的显式 `--cuda-compute f16` 结果包含直接生成 F16 卷积展开列的优化。
每项均通过全部七个原始参考用例，且诊断张量和 mask 与此前 F16 路径逐位一致。
dense 矩阵仍采用 F16 输入、F32 累加／输出，量化权重保留原生压缩 kernel；
这不代表与默认 F32 计算等价。下列三项分别运行三个独立进程，每进程 20 次
完整热调用，共 60 个样本；显存取三次独立 50 ms 采样运行的最大值。
其他图像配置此前的 F16 计时保留在
[实施记录](../docs/plans/20261007-143003-activation-and-runtime-quantization.md)中。

CUDA 使用精简索引和分块转置加速无损布局拷贝，并按存储和计算模式选择执行策略：
所有模式合并 concat 启动；量化图像
默认计算合并融合、检测和掩码阶段，减少内部 host 传输；F16 快速模式采用
融合 head-256 跟踪 attention；图像卷积直接生成 F16 展开列，省去完整 F32
展开张量及其重复转换缓冲。量化权重保留原生压缩矩阵 kernel。
Q8_0 与 Q4_K 的延迟仍接近，低 bit 存储的主要收益仍是减少权重内存。
联合预测和快速计算会改变临时缓冲需求，应同时比较延迟与上表显存。
