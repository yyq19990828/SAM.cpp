# Migrate to official GGML 0.25.3

Created: 2026-09-30 23:18 Asia/Shanghai.
Status: complete. The measurements below are historical; the
[subsequent window/CPU investigation](20261001-002850-metal-window-cpu-performance-official-weights.md)
restores native Metal windows and does not reproduce the historical 13.6% CPU
difference in a controlled comparison. It also records original-weight acceptance.
Planning and implementation explicitly authorized. Validation finished 2026-10-01.

## Scope

Replace the PABannier GGML 0.9.9-based fork at `331b9cba52b23d895bc4ad218c007eb5e667540f`
with official [GGML 0.25.3](https://github.com/ggml-org/ggml/commit/353b63b439f27ab2cc19dac97ab1681ba6d2d084),
fixed at `353b63b439f27ab2cc19dac97ab1681ba6d2d084`. Keep header-only SAM, public
APIs, `internal` layering, checkpoint formats, CPU/Metal selection and precision
contracts. Retain only measured, necessary local GGML corrections.

This is a dependency and kernel migration, not a CUDA/new-model implementation
or an original-checkpoint acceptance claim. Existing supplementary weights and
reference provenance stay unchanged. Do not relax numerical thresholds.

## Findings and approach

- Upstream now implements Metal transpose/depthwise convolutions. Inventory the
  old fork's changes against the operators and shapes actually used; avoid
  carrying unrelated profiling code or already-upstreamed implementations.
- The six-argument scheduler and required convolution helper declarations still
  exist, but compilation and backend execution must prove compatibility.
- Upstream Metal shaders are split under `src/ggml-metal/kernels/`. Dense float
  matrix kernels still stage operands in half. Both vector and matrix F32
  attention configurations contain half Query types; bypassing vector attention
  alone is insufficient on this revision.
- Port explicit `GGML_PREC_F32` dense multiplication to float staging and correct
  threadgroup sizing. Give precise F32 attention a float Query path with matching
  memory layouts and allocation. Keep default/quantized paths unchanged unless a
  separately measured correction is necessary.
- Preserve CPU FP16 storage promotion and graph-side convolution precision
  handling until tests justify a change. Do not duplicate model graphs by backend.
- Shared checkouts remain read-only; patch/build isolated copies. Preparation
  must verify pinned source, patch applicability, resulting file hashes and
  truthful dependency provenance for standalone and caller-owned GGML targets.

```text
Shared official checkout at fixed SHA (read-only)
              |
CMake source copy + small precision patch + exact hashes
              |
SAM runtime/driver adapters -> shared model graphs
              |
arithmetic probes -> complete reference matrix -> session/integration checks
```

## Steps and ownership

1. Coordinator records this plan, locates the shared official checkout, preserves
   current patch/provenance and accepted build artifacts, and records source identity.
2. Metal worker ports the measured precision changes to an isolated source copy,
   runs real GPU probes (matrix tails and short-query attention), and emits a
   frozen patch plus file hashes. No source checkout edits.
3. Core worker audits required operators/API behavior and adapts only necessary
   SAM runtime/model calls; checks CPU compilation and representative execution.
4. Integration worker updates FetchContent, verified patch preparation, dependency
   checks and targeted regressions after the patch is ready. Keep the existing
   source-isolation, self-contained-header and downstream-consumer checks.
5. Coordinator runs the full frozen FP32/CPU, FP16/CPU and FP16/Metal matrix,
   diagnoses any differences without weakening gates, verifies session ownership
   and actual GPU execution, and records latency/memory against the older receipts.
6. Update README, architecture/dependency notices, patch documentation, changelog
   and this plan. Refresh canonical builds only after the new dependency passes.

## Verification

- Arithmetic: direct-device F32/F32 and F16/F32 products including irregular
  dimensions; short-query attention at SAM-relevant head dimensions; precision
  flags and actual GPU execution. No silent CPU replacement for Metal probes.
- API/ownership: CPU and Metal Release/CTest, all independently compiled guarded
  headers, two-TU linking and caller-owned-GGML consumers. Backend accounting
  follows actual assigned handles; test scheduler fixtures against new semantics.
- Models: all seven frozen cases on all three supported precision/backend pairs;
  unchanged tensor, token, box, score and mask gates. Bitwise identity across
  dependency versions is diagnostic, not a substitute for the reference gates.
- Sessions/performance: retained-model ownership, changed prompts/images, caches
  and isolation; record checkpoint, backend, precision, hardware, median latency
  and peak memory for the upgraded dependency. Keep previous receipts intact.
- Tool tests run in the isolated reference environment. Whitespace and patch
  syntax checks preserve required unified-diff context markers and licenses.

Use fresh `build/upstream-*` directories for migration checks; current
`build/cpu`, `build/metal` and earlier reports are the accepted fallback until
validation succeeds. No commit or push is included in this request.

## Progress and results

- Planning: confirmed official SHA/version and inspected current upstream kernel
  precision choices. Repository remains uncommitted; checkpoints/build outputs
  are ignored. No original-checkpoint or CUDA result is inferred from this work.
- API audit: the deprecated matrix/attention precision setters are replaced by
  `ggml_prec_set_acc`. The new source-precision setter supports only matrix RHS
  operands, so it cannot replace the required attention correction.
- Convolution audit: official 0.25.3's convenience helpers force F16 `im2col`
  output for F32/F16 kernels. Preserve the existing SAM precision contract by
  explicitly constructing F32 `im2col`, matrix multiplication and the original
  output layout in SAM's shared convolution wrapper. Keep this out of the GGML
  patch and add a numerical regression that exposes activation rounding.
- Metal scope: float-Query attention applies to SAM's equal 32/64-dimensional
  heads. Larger float-Query variants can exceed the M4 Pro's 32 KiB threadgroup
  limit; their upstream paths remain unchanged. The M4 Pro cannot execute the
  newer Metal tensor-API path. Its memory sizing is reviewed, but neither shader
  compilation nor execution of that branch is verified; this host also lacks
  the standalone Metal compiler.
- Isolated Python converter/reference checks: 5 tests passed.
- Fresh CPU and Metal Release builds passed 8/8 CTest checks each; caller-owned
  CPU and Metal consumers passed 2/2 each. All 32 project headers compile
  independently/repeatedly; the 30 library headers also pass with deprecated
  declarations treated as errors. The current graph uses 94 available GGML APIs.
- Source preparation verifies all 2,283 files against exact original/patched
  tree digests, accepts already-patched archives, repairs generated-source drift,
  and rejects mismatched inputs. Source/output and temporary-output overlap is
  rejected before recursive cleanup. The shared checkout stayed unchanged.
  Receipt: `build/upstream-migration/integration-validation.json`.
- Canonical `build/cpu`, `build/metal`, `build/consumer-cpu` and
  `build/consumer-metal` now use the official revision and pass 8/8, 8/8, 2/2 and
  2/2 CTest checks respectively. Refreshing the old CPU copy exposed a blocked
  read of an obsolete generated file. The old copy is retained under
  `build/upstream-migration/legacy-cpu-source-before-0253`; preparation now checks
  cached contents only when input fingerprints still match. A stale-cache
  regression fails with the former condition and passes with the final code.

### Backend placement and performance limit

All seven Metal cases executed 3,286 Metal nodes and 56 CPU nodes. A separate
`GGML_SCHED_DEBUG=2` trace identifies 28 `WIN_PART` and 28 `WIN_UNPART` nodes on
CPU. The older fork supplies these Metal operations in commit `7a466633`; the
official backend does not contain them. Graph partitions rise
from 6 to 118 per image while the largest compute allocation stays unchanged.
Trace and structured counts are in
`build/upstream-migration/metal-placement.{log,json}`.

Five warmed FP16 Metal runs, performed after other inference/build work stopped,
have median latency 7.420 seconds versus the old dependency's 6.836 seconds
(about 8.5% slower). Peak RSS is 2,652,667,904 bytes versus 2,627,977,216 bytes;
result-cache median is 10.751 ms versus 10.692 ms. These are local M4 Pro
measurements, not a controlled attribution of every timing difference to one
operator. Keep the four-file precision patch scoped and record GPU window
operator coverage as a subsequent optimization. Actual fallback is exposed in
runtime statistics and is part of this upgrade's documented support behavior.

The same converted FP16 weights also pass direct CPU/Metal comparisons for all
70 tensors and six high-confidence detections: maximum normalized L2
0.000151892, minimum mask IoU 1.0, maximum score difference 3.58e-7 and zero
selection differences. Receipt: `build/upstream-migration/backend-agreement.json`.
