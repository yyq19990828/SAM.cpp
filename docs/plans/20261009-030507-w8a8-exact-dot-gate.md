# W8A8 exact dot gate

Created: 2026-10-09 03:05:07, Asia/Shanghai.

## Scope

Continue quantization precision acceptance at the W8A8 arithmetic prerequisite recorded by the frozen v2 policy. The CUDA prototype currently checks at most 512 raw INT32 dots per run; this does not prove all declared output positions. Add an opt-in raw operand/result export and an independent exact INT64 verifier. Preserve the frozen v2 gates, prior probe receipts, model outputs and runtime defaults.

## Approach

1. Extend only the diagnostic CUDA linear probe with a flag that publishes packed W8/A8 rows and the pre-epilogue INT32 matrix, with explicit shape/layout metadata and finite bounds. Keep normal probe behavior and timing unchanged when the flag is absent.
2. Compare every exported dot to a chunked signed INT64 oracle on the exact packed bytes. Verify output shape, K bound, operand range, mode, producer identity, and report worst position and exact mismatch count. Reject modified or incomplete payloads.
3. Check zero/tie/saturation/tail and maximum-K fixtures, then representative real SAM linear shapes on the current CUDA toolchain. Keep the evidence scoped to the executed shapes and modes, and distinguish this arithmetic gate from full SAM W8A8 quality and deployment acceptance.

## Verification

Build the CUDA probe on pinned GGML, run focused validator tests and the applicable Python tool suite, verify produced file hashes and `git diff --check`. Keep the current verified build and required evidence; clean temporary outputs after the cycle.

## Results

The normal probe still saves its former output and performs its existing numerical checks. A separate default-mode run passed `verify_linear_probe.py` and emitted no raw files; duplicate dump arguments and FP8 use of the INT32 flag were rejected before output creation. No SAM runtime or public precision mode changed.

The [exact dot verifier](../../tools/validation/verify_int8_dots.py) reads the native packed bytes and recomputes every dot with signed INT64 products in bounded token chunks. It checks the declared layout, file sizes, input/probe identity, INT8 range, positive finite scales, and the INT32 accumulation bound; any integer difference fails without a numerical tolerance. Tests confirmed tail chunks and detection of a changed final dot, `-128`, truncated data and an unclaimed dump.
