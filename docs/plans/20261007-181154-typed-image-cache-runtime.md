# 类型感知图像缓存的运行时实验

创建：2026-10-07 18:11:54，Asia/Shanghai。状态：实验及质量/性能验收完成；保留内部模式。

## 范围

接续[缓存数值筛选](20261007-173858-image-cache-numerical-screening.md)。F16 已通过
完整 128 张 selection 的逐对象门槛及标注预算；全层 Q8_0 未通过。Q8_0 的
FPN 0/1 消融也已通过，按该固定组合进入运行时实验。512 张 evaluation
在原生 selection 完成、配方冻结后才启用；数值筛选通过不等于可发布或已有加速。

本批先做内部、显式选择的 CUDA 图像实验。生产默认、公共 BackendOptions 和
视频历史状态保持既有契约。待实际质量、性能和内存结果支持后，再决定最小公共
选项，避免将筛选用的任意分层组合直接暴露给用户。

## 实施方法

1. 增加内部带类型的 host tensor，保存唯一紧凑 payload、元素数和行布局。
   上传检查类型、连续性和元素数量；诊断需要 F32 时才按需解码。默认 F32 路径
   不引入额外编码节点或长期双份 host 缓存。
2. 由 backend policy 选择可用缓存类型并检查原生 cast 能力。SAM 3 负责说明
   各缓存的消费者：F16 可覆盖三层；若混合 Q8_0 通过，仅压缩前两层 mask 细节，
   fusion/detection 使用的最低分辨率层保留 F32。形状和例外留在模型适配器。
3. 编码图只将紧凑输出标为 graph roots，直接下载紧凑 bytes；消费图以紧凑
   dtype 分配输入，再由同一设备解码 F32。依赖图决定生存期，不能把源、cast
   输出和分配器保留容量忽略后宣称显存下降。
4. 内部模型加载入口接收不可变的实验模式，公开加载接口仍走默认模式。新增
   独立诊断入口用于最终输出、host payload、上传/下载量和 graph arena 对照。
   图像缓存的试验不作用于视频模型或 tracker features。
5. 用真实图像验证 F32 控制、候选和原始 checkpoint，再冻结配方、运行独立
   512 张评估。若候选不能保住既定逐对象/平均指标，终止该候选的发布。
6. 完整图像、更换提示、完全缓存重放分别计时；正式测量至少三个独立进程、
   每进程至少 20 次 warm 完整调用、baseline/candidate 交错，GPU 串行。
   与已有最优 Q8/Q4 + F16 路径比较；只节省 host/传输时明确标注。

## 验证

- CPU/CUDA 原生 codec、布局和接口边界；非法 dtype、长度、非连续输入拒绝。
- 新独立 Release 构建、头文件独立包含/two-TU、对应 CPU/CUDA CTest。
- F32 默认回归和既有七个图像用例；候选使用 frozen cache/量化门槛，保留
  原始参考与当前已验收模式两种比较，不改写旧 receipts。
- 工具测试、文档检查、`git diff --check`；记录源码/依赖/模型/数据身份，按
  仓库要求清理本批可再生中间物并保留有效构建与不可变证据。

## 结果

### 内部接入与原生预检

`HostTensor` 现在让 FPN 缓存保存唯一 F32/F16/Q8_0 payload；消费图验证行布局后
直接上传紧凑格式、在原设备解码。混合 Q8_0 配方只作用于前两层。后端初始化
检查原生 codec 能力，CPU/Metal 的实验选项明确拒绝；默认 F32 和所有公开视频
入口仍走原模式。新增的 `sam_cache_image_probe` 是内部实验工具，可输出紧凑
逐 query 结果、可选诊断 tensor 和分开的完整/换提示/重复结果计时。

独立 Release 构建通过：CUDA CTest 28/28、CPU CTest 15/15，含新缓存边界、
原生消费计算、头文件独立包含和 two-TU。两者通过调用者提供的已验证 GGML
依赖构建，没有改写上一阶段库；因此本次 CTest 不重复注册 GGML preparation
检查。Metal 缓存模式没有硬件验收或支持声明。

[真实权重预检](../../build/cache-runtime-preflight-v1/sequence.json)覆盖原始 F32
权重/CUDA F32 计算，以及现有 full Q8_0 权重/CUDA F16 计算，各跑默认、F16、
混合 Q8_0 缓存。七个固定用例分别比较原始 checkpoint 与本轮 native baseline。
[136 项检查](../../build/cache-runtime-preflight-analysis-v1/analysis.json)均通过：
候选 FPN 与对应原生编码参考逐值一致；混合 Q8_0 的检测路径未变；默认 full Q8
路径的十个诊断 tensor 及七例最终输出与上一阶段相同。

缓存基线；绝对质量仍相对原始 checkpoint，两个条件不能互相替代。

最终只冻结 **F32 权重/CUDA F32 计算 + FPN 0/1 Q8_0、FPN 2 F32** 一种配方，
见[冻结清单](../../build/native-cache-frozen-recipe-v1.json)。它记录源码、二进制、
依赖、原始 checkpoint、GGUF、数据、门槛、selection 证据和评估脚本身份；
[源码副本](../../build/typed-cache-runtime-sources-v1/hashes.json)保存 native 编译
路径和工具。512 张 evaluation 只比较此候选及相同权重/计算的 F32 缓存基线。
先在两张 selection 控制图上检查原始 oracle 与已归档输出逐字节一致，再进入
独立图片。评估后不依据失败样本修改本轮参数、候选或门槛。

仅质量通过才进入正式性能测量：同一工具、同一输入，三个独立进程，每进程
5 次完整 warmup 后测 20 次完整调用，另测换提示和结果缓存重放；按 AB/BA/AB
交错，内存另用进程采样。既有 Q8/Q4 + F16 计算作为速度/显存对照，明确其
此前七例验收与本次严格 512 张验收的范围区别。若新候选只节省主机载荷或传输，
不宣称达到整图显存或延迟目标；是否提供公共选项仍由质量及实测结果决定。

最终完整重建后，CPU CTest 15/15、CUDA CTest 28/28、隔离环境 Python 工具测试
104/104 再次通过。使用最终二进制补测了量化权重/CUDA F32 联合图路径，
[28 项检查](../../build/native-cache-joint-regression-v1/analysis.json)通过：默认七例
最终检测字段和掩码与旧验收逐值一致，F16/混合 Q8_0 缓存也通过新增误差门槛。
这组属于路径回归，不扩展其独立 COCO 质量资格。上述数值检查可以与 oracle
生成并行；正式性能测量仍要求 GPU 串行。

共享图像缓存类型也经真实视频默认路径回归：hybrid 权重/CUDA F16 的 48 帧
motion 用例完成，[230 项比较](../../build/typed-cache-video-regression-v1/analysis.json)
全部通过，包含最终字段、每帧掩码、去除执行计时后的跟踪决策和四个采样帧的

全部视频场景或新增视频 A8 支持。

### 独立 512 张质量结果

[独立评估](../../build/native-cache-evaluation-v1/metrics.json)已完成，覆盖全部
512 张 evaluation 和 1,676 个提示。原始 oracle 的两张 selection 控制图与旧
参考逐字节一致；没有用 evaluation 拟合或替换配方。原生 F32 缓存基线及混合
Q8_0 候选均为 **512/512 张通过**原始 checkpoint 逐对象门槛，候选也为
512/512 张通过相同 native 基线的新增误差门槛。

| 模式 | Prompted mask AP | 正提示 union-mask mIoU | 负提示检测数 |
| --- | ---: | ---: | ---: |
| 原始 checkpoint | 0.4714805644 | 0.6992940220 | 3 |
| native F32 缓存 | 0.4714805644 | 0.6992936993 | 3 |
| native 混合 Q8_0 缓存 | 0.4715276659 | 0.6992986661 | 3 |

平均指标在冻结预算内；这点微小数值差异不作为质量提升声明。AP 的范围是固定
自选 COCO 子集的 prompted image/category pairs、score > 0.5 输出，不是完整
val2017 AP。该结果只为冻结的 F32 权重/CUDA F32 计算组合提供图像质量证据，
不扩展到 F16、量化权重、其他设备或视频。质量通过后开始正式交错性能测量。

进一步核对归档输出，候选与 native F32 基线的全部 1,676 个提示、每提示
200 个 query 的置信度和边框均逐值一致。按固定逐对象门槛比较的 2,916 个掩码
中，最小 IoU 为 0.988764；缓存量化只改变了这里的 mask 细节。

### 正式性能、内存与发布决定

[测量记录](../../build/native-cache-performance-v1/sequence.json)及
[汇总](../../build/native-cache-performance-v1/comparison.json)完成。RTX 4090、CPU
4 线程，1800×1200 truck 图像；完整调用包含 `set_image` 与分割，更换提示交替
truck/wheel，结果重放单独测量。每个配置三个独立计时进程，5 次 warmup 后
20 次完整调用，基线/候选按 AB/BA/AB 交错；下表时间汇总 60 次样本。内存另用
三个进程，NVML 每 10 ms 绑定目标 PID 采样；GPU 数值是采样下界，不能视为
精确瞬时峰值。GPU 没有并行模型工作负载。

| 权重/计算及缓存 | 整图中位数 / P95，ms | 换提示中位数，ms | 结果重放中位数，ms | 采样 GPU，GB | 峰值 RSS，GB |
| --- | ---: | ---: | ---: | ---: | ---: |
| F32/F32，F32 缓存 | 503.239 / 512.264 | 151.990 | 12.591 | 4.777 | 0.995 |
| F32/F32，混合 Q8_0 缓存 | 442.718 / 450.142 | 133.206 | 12.624 | 4.784 | 0.843 |
| 既有 full Q8_0/F16，F32 缓存 | 333.086 / 337.264 | 149.042 | 12.612 | 2.227 | 1.208 |
| 既有 full Q4_K/F16，F32 缓存 | 334.870 / 339.417 | 149.459 | 12.588 | 1.917 | 1.214 |

GB 为十进制；内存列取三个独立进程峰值的中位数。基线三个进程整图中位数为
507.314/500.116/502.929 ms，候选为 442.145/442.132/443.195 ms。Q8/Q4 对照
使用此前七例验收范围，其所有本次进程的 truck 最终输出仍与旧验收逐值一致；
不把这些对照计为通过本轮 512 张严格质量。

候选相对相同权重/计算基线，整图中位数降低 **12.026%**、P95 降低 **12.127%**、
换提示中位数降低 **12.358%**，主机峰值 RSS 中位数降低 **15.302%**。
FPN payload 降低 **69.940%**。但三个基线 GPU 采样峰值均为 4,777,312,256 bytes，
三个候选均为 4,783,603,712 bytes，即增加 6,291,456 bytes（**0.132%**）。
逻辑 GGML arena 从 1,072,777,632 降至 1,001,778,336 bytes，没有转化为整图
GPU 峰值下降。arena 计数不覆盖全部 CUDA 库、临时缓冲及保留容量，不能用
它替代实际进程采样，也不在缺少独立分配归因时将差额归因于某一个 buffer。

[判定](../../build/native-cache-performance-v1/decision.json)：严格图像质量通过，
但未达到路线图的均衡模式显存降幅或节省显存模式目标。**本轮不新增公共缓存
精度选项**，保留类型感知 host storage、原生 codec 检查及内部实验工具。该
固定候选的有效收益是这一配置下的延迟、主机载荷和传输量；不宣传其节省显存，
也不将它叠加到未通过本轮严格质量的权重/计算组合。

如后续继续推进，应针对设备中间张量和保留缓冲的真实生存期优化，并使用新的
计划和独立验收；本轮门槛、输出及失败候选不再改写。
